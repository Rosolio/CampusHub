# 《AI 协作契约》
团队名称：[还没想好]
日期：[2026年04月16日]

第一条：AI 使用原则
- AI 是工具，工程师是责任主体
- 所有 AI 输出必须经过人工审查后才能合入项目

第二条：AI 使用范围
- 允许使用 AI 的场景：需求文档初稿生成、代码注释编写、简单功能代码片段生成、测试用例初稿设计、README.md 初稿生成、架构决策参考。
- 禁止直接使用 AI 输出（需额外审查）的场景：核心业务逻辑代码、安全相关代码（权限校验/数据加密）、架构设计文档最终版、需求文档最终版。
- 完全禁止使用 AI 的场景：代码审查结论判定、缺陷修复方案决策、团队核心规则制定（编码规范/协作契约）、项目里程碑规划。

第三条：过程记录要求
- 所有与 AI 的交互 Prompt 统一存储在仓库 `docs/P0/AI_prompt_log.md` 中
- Git commit message 必须标注 [AI-assisted] 或 [Human-written]
- 每阶段填写《AI 协作反思日志》（存储在仓库 docs/对应阶段目录）

第四条：代码合入规则
- AI 生成的代码必须通过至少一名团队成员的 Code Review
- 每位成员每个编码阶段至少有 2 个完全手写的核心函数

第五条：违约处理
- 首次违约：团队口头提醒，违约人补充审查/重写相关内容，例会说明问题原因；
- 二次违约：违约人负责该阶段不少于3个模块的额外代码审查，提交书面反思报告；
- 多次违约：暂停核心模块分工，重新学习契约并通过团队考核后恢复。

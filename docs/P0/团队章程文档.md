## 二、角色分工阐述
### 1. 需求负责人（邢高锦）
- 角色理解：需求负责人是连接用户/业务与开发团队的核心桥梁，需精准捕捉、梳理并表达需求，确保团队对需求的理解一致，同时通过用例建模将抽象需求转化为可落地的开发指引。
- 核心职责与目标：
    - 职责：需求调研与收集、PRD文档撰写、用例建模（用例图/场景描述）、需求变更管理、同步需求细节。
    - 目标：保障需求无歧义、全覆盖，确保开发方向匹配业务目标，降低需求偏差导致的返工。

### 2. 架构负责人（玉单扬）
- 角色理解：架构负责人是项目技术总设计师，需结合需求选择适配技术栈，设计高可用、易扩展的系统架构，通过ADR记录关键技术决策依据。
- 核心职责与目标：
    - 职责：技术选型、整体架构设计、模块拆分、ADR文档撰写、技术风险评估与规避。
    - 目标：确保技术架构适配项目规模与长期发展，降低技术债务，提升开发效率。

### 3. 开发负责人（谢浩天）
- 角色理解：开发负责人是编码环节核心管理者，需保障代码质量与规范，主导核心模块开发，通过代码审查统一团队编码风格与质量。
- 核心职责与目标：
    - 职责：制定编码规范、组织代码审查、核心模块开发、解决技术难题、指导编码实践。
    - 目标：保障代码可读性/可维护性/可复用性，按时完成核心模块开发，提升团队编码水平。

### 4. 测试负责人（吴雨泽）
- 角色理解：测试负责人是项目质量守护者，需制定全面测试策略，设计覆盖关键场景的测试用例，通过多维度测试保障交付物质量。
- 核心职责与目标：
    - 职责：制定测试策略（单元/集成/系统测试等）、设计测试用例、执行测试并反馈问题、跟踪缺陷修复、把控质量门禁。
    - 目标：提前发现并规避质量问题，确保交付产品功能完整、稳定可靠。

## 三、AI工具链选型
### 1. AI编程助手
| 候选工具           | 评估结果 | 选择/不选择理由                                                                                  |
|----------------|------|-------------------------------------------------------------------------------------------|
| Codex（OpenAI）  | 选择   | 由OpenAI专为代码生成设计，底层模型适配多编程语言，自定义Prompt灵活性高；支持本地/API调用两种方式，适配团队定制化需求；核心功能免费开放，满足项目全周期使用。    |
| GitHub Copilot | 不选择  | 基于Codex封装但自定义扩展能力弱，Prompt适配性受限；团队需更灵活的代码生成控制逻辑，Copilot封装化设计无法满足；部分高级功能需付费订阅，性价比低于原生Codex。 |

### 2. AI对话工具
| 候选工具           | 评估结果 | 选择/不选择理由                                                                                        |
|----------------|------|-------------------------------------------------------------------------------------------------|
| ChatGPT（5.4版本） | 选择   | 5.4版本相比前代提升了技术文档生成精度、多轮对话逻辑连贯性，对需求文档/架构文档的专业术语处理更精准；团队已完成5.4版本接口适配，使用门槛低；支持长文本上下文理解，适配大型文档生成场景。 |
| 文心一言           | 不选择  | 技术文档专业性与英文术语处理准确性不足；无5.0+版本的深度上下文理解能力，长文档生成易出现逻辑断裂；团队无使用经验，学习成本高。                               |

### 3. AI代码审查工具
| 候选工具                      | 评估结果 | 选择/不选择理由                                                                          |
|---------------------------|------|-----------------------------------------------------------------------------------|
| CodeRabbit                | 选择   | 与GitHub集成便捷，可自动识别语法/性能/安全问题，支持自定义规则；免费版满足中小项目需求；可结合Codex生成的代码特征定制审查规则，适配团队AI编程习惯。 |
| AI Code Review（GitLab插件版） | 不选择  | 仅适配GitLab生态，平台切换后无法使用；免费版功能有限，高级能力需付费；无针对Codex生成代码的专属审查规则，适配性差。                   |

### 4. AI测试工具
| 候选工具      | 评估结果 | 选择/不选择理由                                                                       |
|-----------|------|--------------------------------------------------------------------------------|
| Testim AI | 选择   | 支持自动生成测试用例、UI自动化测试，可集成CI流水线；免费试用版满足初期测试需求；可对接ChatGPT 5.4接口，基于需求文档自动生成高匹配度测试场景。 |
| 讯飞AI测试    | 不选择  | 聚焦语音/自然语言测试，通用软件测试适配性差；团队无使用经验，学习成本高；无法与ChatGPT 5.4/Codex形成工具链协同。              |

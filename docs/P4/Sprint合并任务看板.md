# Sprint 合并任务看板

## 1. 规划原则

- 以 P0 能跑通完整主流程为第一优先级
- P1 功能做到"基本可用"，但不以牺牲主流程稳定性为代价
- P2 功能在保证主流程前提下选择性推进
- 单个任务控制在 2-4 小时量级
- 结合 `dev` 分支实际实现，状态分为：已完成、基本完成

## 4. 风险识别（已消除）

| 风险类型 | 说明 | 当前判断 |

# 用例描述

**用例1：发布任务**

**用例名称**：发布任务

**参与者**：用户

**前置条件**：

- 用户已登录
- 已完成实名认证

**基本流**：

1.  用户进入发布页面
2.  选择任务类型
3.  填写任务信息
4.  点击发布
5.  系统校验信息合法性
6.  发布成功，任务进入待接单状态

**替代流**：

- 3a：信息不完整 → 提示补充
- 5a：内容违规 → 拦截发布

**后置条件**：

- 任务成功发布并可被搜索

**用例2：接单并完成任务**

**参与者**：用户（接单者）

**前置条件**：

- 用户已登录
- 任务处于“待接单”状态

**基本流**：

1.  浏览任务列表
2.  点击任务详情
3.  点击“接单”
4.  系统匹配成功
5.  双方可交换联系方式
6.  任务执行
7.  发布者确认完成

**替代流**：

- 3a：任务已被接 → 提示失败
- 7a：用户不确认 → 进入评价或仲裁

**后置条件**：

- 任务状态变为“已完成”或“仲裁中”

**用例3：评价与仲裁**

**用例名称**：评价与仲裁

**参与者**：学生用户、管理员

**前置条件**：

- 任务已完成

**基本流**：

1.  双方进行评分（1-5星）
2.  系统判断评分结果
3.  评分均 ≥3星判定成功
4.  可能进行现金或积分支付
5.  更新信用分和经验分

**替代流**：

- 3a：评分差异大 → 进入仲裁流程
- 3b：评分差异大 → 用户提交纠纷
- 4a：支付失败，进入待支付状态
- 5a：管理员介入处理并裁决

**后置条件**：

- 更新用户信用分

用户故事：

1、作为学生用户，我希望能够发布任务，以便解决日常生活问题\[Must\]  
验收标准：

- 能够填写任务信息；
- 任务能够成功发布并被其他用户看到；

2、作为学生用户，我希望能够接单，以便获得报酬或经验值\[Must\]  
验收标准：

- 能够浏览任务列表；
- 能够成功接单；
- 接单后任务状态正确更新；

3、作为学生用户，我希望能够进行实名认证，以便提高平台安全性\[Must\]  
验收标准：

- 能够通过学号和邮箱完成认证；
- 系统显示认证标识；

4、作为学生用户，我希望能够进行支付，以便完成任务交易\[Must\]  
验收标准：

- 支持现金或积分支付；
- 支付成功后系统提示；

5、作为学生用户，我希望能够对任务进行评价，以便维护信用体系\[Must\]  
验收标准：

- 能够对任务进行评分；
- 系统更新信用分；

6、作为学生用户，我希望能够匿名发帖，以便表达个人情绪\[Should\]  
验收标准：

- 发帖时可选择匿名；
- 发帖后不显示用户身份信息；

7、作为学生用户，我希望能够找搭子，以便进行社交活动\[Should\]  
验收标准：

- 能够发布搭子需求；
- 能够查看其他用户的搭子信息；

8、作为学生用户，我希望能够搜索任务，以便快速找到需要的任务\[Should\]  
验收标准：

- 支持按类型筛选任务；
- 支持按时间或价格排序；

9、作为学生用户，我希望能够交换联系方式，以便线下沟通\[Should\]  
验收标准：

- 接单后可以查看对方联系方式；
- 联系方式显示正常；

10、作为学生用户，我希望能够接收消息通知，以便及时获取信息\[Should\]  
验收标准：

- 能够接收系统通知；
- 能够接收任务状态变更提醒；

11、作为学生用户，我希望能够获得经验值，以便提升等级\[Could\]  
验收标准：

- 完成任务后增加经验值；
- 经验值正确显示；

12、作为学生用户，我希望能够查看排行榜，以便获得成就感\[Could\]  
验收标准：

- 能够查看用户排行榜；
- 排行榜数据正确显示；

13、作为学生用户，我希望能够点赞和评论，以便与他人互动\[Could\]  
验收标准：

- 能够点赞帖子；
- 能够发表评论；

14、作为管理员，我希望能够封禁违规用户，以便维护平台和谐氛围\[Must\]  
验收标准：

- 能够禁用用户
- 被禁用用户无法登陆

15、作为管理员，我希望能够处理用户纠纷，以便维护平台公平性\[Must\]  
验收标准：

- 能够查看纠纷详情和双方的具体情况
- 能够方便地给出仲裁结果
- 待处理的纠纷有消息提醒

## 对3.3问题的回答：

1、AI生成的内容涵盖了大部分异常流，但可能会遗漏一些，例如AI未考虑核心用例3中的4a支付失败。

2、对于大部分简单的验收标准，AI生成的内容是具体可测试的，但是在某些情况下AI生成的内容不够具体，例如第15条用户故事中处理用户纠纷是管理员的工作，平台应当希望管理员尽快处理纠纷，所以消息提醒是合理的，但是AI未考虑这一点，导致验收标准缺乏完整性。

这表明AI更擅长生成功能性描述，但在涉及系统交互、时效性和非功能需求时，往往缺乏深入考虑，仍需人工补充。

# P2 Prompt 日志

## 1. 架构风格直接咨询

**Prompt**

> 我们要做一个校园互助服务平台，支持学生发布和接单任务、二手交易、找搭子、匿名树洞、评价仲裁和消息通知。推荐使用什么架构？

**AI 回答摘要**

推荐前后端分离架构，前端负责页面展示，后端提供 REST API。后端可采用 MVC 或分层架构，按用户、任务、社区、评价、消息等功能划分模块。未来用户量扩大后可以考虑微服务。

**人工处理**

保留“前后端分离”和“分层”的建议，但认为回答过于通用，缺少对团队规模、周期、隐私和部署成本的分析。

## 2. 带项目约束的架构咨询

**Prompt**

> 我们团队 4 人，课程项目周期 10 周，系统是校园互助服务平台。需求包括柔性实名认证、匿名树洞、多类型任务发布、积分激励、评价仲裁、管理员审核。预计校园内 500 人高峰在线。技术基础是 Vue 3、Spring Boot、MySQL、Redis。请在开发复杂度、可维护性、性能、安全、10 周可行性之间权衡，推荐架构。

**AI 回答摘要**

推荐前后端分离 + 模块化分层单体。理由是该方案开发复杂度适中、便于团队并行、部署简单，能通过缓存、索引和分页满足校园级并发。微服务和事件驱动不适合作为第一版主架构，但可以在消息通知、内容审核、积分结算等流程保留扩展点。

**人工处理**

采纳为最终架构方向，并补充了 Controller / Service / Mapper 分层职责、模块依赖图和接口定义。

## 3. 多架构方案对比

**Prompt**

> 请对校园互助服务平台的 MVC / 分层架构、微服务架构、事件驱动架构做对比，说明每种方案的优缺点、适用条件，以及我们在 10 周课程项目中应该如何选择。

**AI 回答摘要**

AI 输出了三种架构的优缺点：分层架构简单直接；微服务可扩展性强但成本高；事件驱动适合异步通知和削峰，但会增加一致性和调试复杂度。建议首版采用分层单体，局部借鉴事件驱动。

**人工处理**

整理为候选架构对比表，并加入“团队学习成本”和“10 周内可行性”两个课程项目关键维度。

## 4. 架构师角色审查

**Prompt**

> 请扮演一名有 10 年经验的软件架构师，审查我们的校园互助平台需求。你需要特别关注隐私、安全、10 周落地和后续可扩展性，给出架构建议、模块划分和关键风险。

**AI 回答摘要**

AI 建议采用模块化单体，并强调匿名树洞和实名交易需要不同身份展示策略。它建议外部校园认证、支付、内容审核通过适配层接入，避免核心业务直接绑定第三方实现。

**人工处理**

采纳“身份分层展示”和“外部系统适配层”，但删除了首版真实支付托管、复杂消息队列和过度风控设计。

## 5. ADR 初稿生成

**Prompt**

> 基于最终选择的前后端分离 + 模块化分层单体架构，为校园互助服务平台生成 3 条 ADR。每条 ADR 包含状态、背景、决策、理由、后果，并说明 AI 初稿和人工修订差异。

**AI 回答摘要**

AI 生成了三条 ADR：选择分层架构、使用 JWT、使用 MySQL + Redis。每条包含基本结构，但人工修订差异较笼统。

**人工处理**

扩展为四条 ADR：架构风格、柔性实名、数据存储、REST + JWT。每条加入 diff 标记，突出 AI 初稿遗漏的质量属性权衡。

## 6. 模块与接口定义

**Prompt**

> 根据 P1 需求规格说明书，为校园互助服务平台划分模块，明确每个模块的职责边界、模块间依赖关系和主要 REST API。需求包括认证用户、任务发布接单、匿名树洞、找搭子、评论点赞、评价仲裁、消息通知和管理员审核。

**AI 回答摘要**

AI 将系统划分为认证与用户、任务、社区、评价仲裁、消息、后台管理、外部系统适配等模块，并给出接口名称和数据格式建议。

**人工处理**

结合当前后端配置和数据库表，补充了 tasks、task_participants、task_comments、task_reviews、messages、feedback 等数据归属，并调整接口路径为 `/api/...` 风格。
